# Phase 2 최종 비교와 사례 연구

## Before와 After

Before는 실제 GPU 기준선 3회 원본(`runs/real-gpu-before.json`), After는 최신 main에서 다시 실행한 데스크톱·CPU ×4 각각 3회 원본(`runs/phase2-final-after.json`)이다. 고정 조건은 Chrome 창 모드, 1365×768, HTTP 캐시 비활성화, Weather 고정 응답, 각 기상 프리셋 20초다.

## 변경과 결과

- 유지된 개선: 썸네일 977,995 → 213,019 B(764,976 B, 78.2% 감소), 전체 배포 산출물 14,299,816 → 13,534,839 B(764,977 B, 5.3% 감소), Cesium·썸네일 immutable 캐시 헤더, 정적 성능 예산 CI.
- 롤백한 실험: SceneCanvas 지연 로딩은 FCP/LCP와 Viewer 준비를 악화했고, rAF 강수 루프는 세 프리셋 p95를 모두 회귀시켰다. 두 구현은 `main`에 남기지 않았고 측정 원본·원인·대안을 문서화했다.
- 최종 런타임 3회 중앙값은 데스크톱 FCP/LCP 640 → 732ms, Viewer 669 → 794.1ms, CPU ×4 FCP/LCP 940 → 1,060ms, Viewer 1,588 → 2,078.1ms로 목표에 미달했다. 정적 전달 변경으로 이 값을 개선이라고 주장하지 않는다.

## 롤백 조건

최종 문서가 원시 결과와 다른 수치를 제시하거나, 캐시 헤더가 공개 Production에서 누락되거나, 정적 예산이 정상 build를 거짓 실패시키면 해당 문서·헤더·게이트를 각각 되돌리고 원인을 재검증한다.
