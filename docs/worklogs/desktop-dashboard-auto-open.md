# 작업 일지: desktop-dashboard-auto-open

## 기본 정보

- 날짜: 2026-09-08
- 브랜치: practice/my-own-practice
- 관련 PR: 없음
- 목표: 모바일에서 접은 대시보드가 데스크톱(`lg`, 1024px 이상) 전환 시 항상 다시 열리게 한다.

## 기준선과 가설

- 기준선: 대시보드 열림 상태는 컴포넌트 내부 `ref`만 사용하며, 화면 폭 변화는 감시하지 않는다.
- 가설: 데스크톱 폭 진입 시 진행 중인 접기 애니메이션을 취소하고 렌더링/열림 상태를 모두 `true`로 복원하면 패널이 항상 표시된다.
- 성공 기준: 모바일에서 패널을 접은 뒤 너비를 1024px로 바꾸면 패널 DOM이 다시 렌더링된다.

## 변경 내용

- `DashboardOverlay`에 데스크톱 폭 진입 시 대시보드를 강제로 여는 resize 처리기를 추가한다.
- 모바일 접기 애니메이션이 완료 콜백으로 다시 닫지 않도록 데스크톱 전환 시 활성 tween을 취소한다.
- 모바일→데스크톱 전환 회귀 단위 및 Playwright E2E 테스트를 추가한다.

## 검증

- 실행 명령: `pnpm exec vitest run src/widgets/dashboard/DashboardOverlay.spec.ts --reporter=verbose`, `pnpm exec playwright test e2e/dashboard.spec.ts`
- 테스트 결과: 단위 테스트 14/14 통과. 추가한 Playwright 모바일→데스크톱 전환 시나리오 1/1 통과. 전체 `e2e/dashboard.spec.ts` 실행은 테스트 러너 완료 상태를 수집하지 못해, 신규 시나리오를 단독으로 재실행해 확정했다.
- Before → After: 화면 폭 변경 미감시/패널 유지 불가 → 1024px 이상 전환 시 패널 렌더링 및 열림 상태 복원.

## 판단과 롤백

- 판정: 테스트 통과 시 유지.
- 위험: 데스크톱 폭에서 사용자가 의도적으로 패널을 닫아 둘 수 없지만, 데스크톱에서는 항상 열려야 한다는 요구사항과 일치한다.
- 롤백 조건: 데스크톱에서 패널 상시 노출 요구가 변경되거나, resize 처리로 애니메이션 상태 오류가 재현될 때.
- 다음 작업: 브라우저 E2E에서 실제 모바일→데스크톱 viewport 전환을 추가 검증한다.
