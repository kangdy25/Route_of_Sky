# 작업 일지: 성능 사례 연구 통합

## 기본 정보

- 날짜: 2026-08-14
- 브랜치: `codex/performance-case-study-consolidation`
- 목표: Phase별로 흩어진 성능 최적화 설명을 하나의 포트폴리오 사례 연구로 재구성하고, 원본 측정·의사결정 문서는 근거 자료로 보존한다.

## 기준선과 가설

- 기준선: README는 Phase 1, Phase 2, Phase 3을 각각 독립 섹션으로 노출하고, `docs/performance/case-study.md`는 Phase 1 사례 연구만 담고 있다.
- 가설: 공개 문서를 전달·API·렌더링·검증 체계라는 문제 영역으로 구성하면 성과와 제약을 한 흐름에서 이해할 수 있다.
- 성공 기준: 통합 문서에서 확인 가능한 모든 수치가 원본 문서로 연결되고, 렌더링 미확정 결론과 측정 한계가 누락되지 않는다.

## 변경 내용

- 기존 문서·수치·PR 링크를 확인했다.
- 기존 `docs/performance/case-study.md`는 `phase1-case-study.md`로 보존하고, 같은 경로에 문제 영역별 통합 사례 연구를 작성했다.
- README의 세 개 Phase 섹션을 하나의 성능 사례 연구 요약과 통합 문서 링크로 교체했다.
- 통합 문서는 정적 전달, Weather API, 렌더링 품질, 검증 체계, 최종 결론 순서로 구성했다.
- 수치가 변동만 보여 주는 실제 GPU 재측정은 표에 남기되, 코드 변경이 없으므로 최적화 성과로 귀속하지 않는 점을 명시했다.

## 검증

- 로컬 Markdown 링크와 이미지 경로를 검사해 모두 해석되는 것을 확인했다.
- 성능 문서와 작업 일지에서 API 키·원시 API URL·환경 변수 문자열이 없는 것을 확인했다.
- `pnpm run lint`, `pnpm run test:unit --run`(256개), `pnpm run build`, `pnpm run perf:budget`, `pnpm run test:e2e`(7개)를 통과했다.
- 수치·애플리케이션 런타임을 변경하지 않은 문서 구조 작업이므로 실제 GPU 3회 재측정은 수행하지 않았다. 기존 원본 JSON과 비교표를 그대로 연결했다.

## 판단과 롤백

- 판단: 공개 진입점만 통합하고 Phase별 원본 JSON·비교표·작업 로그는 삭제하지 않는다.
- 위험: 서로 다른 측정 환경의 수치를 잘못 합산해 성과로 표시할 수 있다.
- 롤백 조건: 출처·환경·인과관계가 불분명한 수치는 통합 표에서 제거하고 원본 링크만 남긴다.
- 최종 판단: 통합 문서는 배포에 남은 정적·API 최적화와 안전한 렌더링 미확정 결론을 함께 공개한다. Phase별 문서는 원본 근거로만 남긴다.
