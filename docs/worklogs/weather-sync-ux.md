# 작업 일지: 날씨 동기화 상태 UX

## 기본 정보

- 날짜: 2026-08-15
- 브랜치: `codex/weather-sync-ux`
- 관련 PR: #35
- 목표: 실시간 날씨 요청의 로딩·성공·캐시·실패 상태와 수동 재시도 경로를 대시보드에 명확히 제공한다.

## 기준선과 가설

- 기준선: 날씨 store는 로딩, 데이터 출처, 갱신 시각, 오류 메시지와 만료 캐시 복구 상태를 관리하지만 UI는 이를 표시하지 않는다.
- 가설: 헤더 상태와 오류 배너에서 데이터 출처·갱신 시각·재시도를 제공하면, 사용자가 카드 값의 최신성 및 복구 방법을 즉시 이해할 수 있다.
- 성공 기준: 모든 동기화 상태가 한국어 접근성 안내로 표시되고, 실패·만료 캐시 상태에서 중복 요청 없이 현재 지역을 강제 갱신할 수 있으며, 기존 지역 변경·캐시·수동 렌더링 흐름이 유지된다.

## 변경 내용

- `WeatherSyncStatus`를 추가해 헤더에 로딩, 네트워크, 유효 캐시, 만료 캐시, 초기 실패 상태와 마지막 갱신 시각을 접근 가능한 상태 영역으로 표시한다.
- `DashboardOverlay`에 오류·만료 캐시 배너와 재시도 버튼을 추가했다. 안내 문구는 고정된 한국어 문구만 사용해 원본 API 오류를 표시하지 않는다.
- 재시도 이벤트는 현재 선택 지역의 강제 갱신으로 연결했고, 요청 중에는 버튼을 비활성화한다. 기존 Settings의 현재 날씨 렌더링 동작은 유지한다.
- 단위·E2E 테스트에 상태 문구, 오류 안내 비노출, 재시도, 초기 실패 복구, 만료 캐시 복구를 추가했다.

## 검증

- 실행 명령: `pnpm exec eslint .`, `pnpm test:unit --run`, `pnpm build`, `pnpm run perf:budget`, `pnpm test:e2e`, `pnpm exec playwright test --workers=1`.
- 테스트 결과: lint 통과. 단위 테스트 35개 파일·266개 통과. build 통과. `perf:budget`은 JS gzip 87,702/92,160B, CSS gzip 15,146/18,432B, dist 13,539,613/14,292,091B, thumbnail 213,019/256,000B로 통과했다. E2E는 sandbox 로컬 포트 제한으로 첫 실행이 중단됐고, 승인 환경의 병렬 실행에서 기존 대시보드 초기화 시간 초과를 확인한 뒤 단일 워커 전체 재실행에서 통과했다.
- Before → After: UI 표시 기능 추가 작업으로 기존 성능 수치 변경을 목표로 하지 않는다. 정적 예산은 모두 한도 내이며 실제 GPU 측정은 수행하지 않는다.

## 판단과 롤백

- 판정: 통과. 날씨 동기화 상태와 수동 재시도 UX를 유지한다.
- 위험: 상태 안내가 헤더 레이아웃을 과도하게 차지하거나, 실패 안내가 원본 API 오류를 노출할 수 있다.
- 롤백 조건: 재시도가 중복 요청을 만들거나 기존 지역·캐시 흐름을 깨뜨리면 상태 UI와 재시도 연결 변경을 되돌린다.
- 다음 작업: PR에서 diff·테스트·오류 메시지 비노출·문서 누락을 자체 검토하고 병합한다.
