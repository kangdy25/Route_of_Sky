# 작업 일지: 테스트 기대값 정렬

## 기본 정보

- 날짜: 2026-09-04
- 브랜치: `practice/my-own-practice`
- 관련 PR: 예정
- 목표: 현재 구현과 불일치하는 단위 테스트 기대값을 정렬해 전체 테스트 스위트를 복구한다.

## 기준선과 가설

- 기준선: 단위 테스트 279개 중 13개가 오래된 기상 라벨, HTTP 오류 메시지, Tailwind 클래스, 온도 게이지 규칙을 기대해 실패한다.
- 가설: 테스트만 현재 구현의 공개 동작에 맞추면 기능 코드를 바꾸지 않고 전체 단위 테스트가 통과한다.
- 성공 기준: 실패한 13개 테스트가 현재 구현의 라벨·메시지·스타일 속성·중립값 규칙을 검증하며 전체 단위 테스트가 통과한다.

## 변경 내용

- 강수량·강설량·가시거리의 최신 라벨 기대값을 반영했다.
- HTTP 오류의 상태 코드 기반 오류 메시지 기대값을 반영했다.
- Tailwind v4 클래스 이름과 동일 최저/최고 기온의 50% 중립 게이지 규칙에 맞춰 selector와 기대값을 정렬했다.

## 검증

- 실행 명령: `pnpm test:unit -- --run`, `pnpm build`, `pnpm test:e2e`
- 테스트 결과: 단위 테스트 36개 파일·279개 통과, build 통과, Playwright E2E 9개 통과.
- Before → After: 단위 테스트 279개 중 13개 실패 → 279개 중 279개 통과, 절대 차이 13개, 개선율 100%, 목표 통과. 성능 수치 변경을 목표로 하지 않는다.

## 판단과 롤백

- 판정: 통과. 현재 구현의 공개 동작을 테스트로 유지한다.
- 위험: 구현 의도와 다른 테스트 기대값을 현재 동작에 맞추는 과정에서 회귀를 놓칠 수 있다.
- 롤백 조건: 수정한 기대값이 제품 요구사항과 다르다고 확인되면 테스트 변경을 되돌리고 구현 변경 여부를 다시 판단한다.
- 다음 작업: 전체 단위 테스트와 build, E2E를 실행한 뒤 결과를 기록한다.
